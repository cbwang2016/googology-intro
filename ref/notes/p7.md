## 1. Computability theory (Ch.25) — exact content

### 1.1 Recursive functions [BOOK]
- **Def 25.1 (primitive recursive functions, 原始递归函数).** Base functions: zero O(x)=0, successor S(x)=x+1, projections Pⁿᵢ(x₁..xₙ)=xᵢ. Closed under composition h(x)=f(g₁(x),…,g_k(x)) and the primitive recursion scheme h(x,0)=f(x), h(x,y+1)=g(x,y,h(x,y)).
- Example: addition, built as x+0=x and x+y′=(x+y)′. Also primitive recursive: constants, x·y, x^y, x!, sign σ, δ, pred, truncated subtraction ∸, quo, rem.
- Diagonal argument: enumerate the primitive recursive functions as g₀, g₁, …. Then F(n)=gₙ(n)+1 is intuitively computable but not primitive recursive.
- **Ackermann function:** Ack(0,n)=n+1; Ack(m,0)=Ack(m−1,1); Ack(m,n)=Ack(m−1,Ack(m,n−1)). For every unary primitive recursive f there is an a with f(y)<Ack(a,y) for all y. So Ack(y,y)+1 is not primitive recursive. Proof: otherwise it would be < Ack(e,y); set y=e and you get a contradiction.
- **Def 25.2 (regular minimisation):** g(x)=μy[f(x,y)=0], where f is total and ∀x∃y f(x,y)=0. The recursive functions are the smallest class containing the initial functions and closed under composition, primitive recursion and regular minimisation.
- **Def 25.3 (partial recursive):** g(x)=μy[∀z≤y (f(x,z)↓) ∧ f(x,y)=0]. The book explains why every earlier point must be defined: you cannot skip a divergent point, because you can't tell effectively that it diverges.
- **Thm 25.2 (Kleene normal form):** there are a primitive recursive U and a primitive recursive predicate T such that every partial recursive f has an index e with f(x)=U(μz T(e,x,z)).
- **Thm 25.3:** recursive = partial recursive and total.
- **Thm 25.4:** there is a universal partial recursive Φ(e,x).
- **Thm 25.5:** there is no universal *total* recursive function.
- **Thm 25.6 (Kleene recursion theorem):** for every recursive f there is an e with φ_{f(e)}=φ_e.
- **Def 25.4 / Thm 25.7:** recursively enumerable sets; equivalent characterisations (range of a partial recursive function, domain of a partial recursive function, ∃y R(x,y), …).

### 1.2 λ-calculus [BOOK]
- **Def 25.5 (terms):** variables; (λx.M); (M N).
- **Def 25.6 (operations):** α-conversion; β-reduction ((λx.M)N)→M[x:=N].
- Ω=(λx.xx)(λx.xx) β-reduces to itself forever. This is the λ-calculus version of non-halting.
- Church numerals: 0≡λsz.z, 1≡λsz.s(z), …. Then S≡λabc.b(abc), plus≡λmnfx.mf(nfx), mult≡λmnfx.m(nf)x, exp≡λbn.nb, pred≡λnfx.n(λgh.h(gf))(λu.x)(λu.u). Booleans true≡λab.a, false≡λab.b, plus and/or/not/xor/if.
- Y≡λy.(λx.y(xx))(λx.y(xx)), with YR→R(YR).
- A 7-byte λ-term beats Graham's number: `(λ11)(λ1(1(λλ12(λλ2(21)))))` (de Bruijn indices). The book also gives a 49-byte term at BO level.
- "λ-calculus and recursive functions are equivalent". The book labels this 定义25.7, but it is really a theorem.

### 1.3 Turing machines (as used for BB) [BOOK]
- Model (L452–489): a two-way infinite tape (两端无穷的纸带), with each cell 0 or 1; one head; finite states A,B,C,…; a special halt state H (also written Z in the tables).
- Each step: read the current cell and state, write 0/1, move L/R one cell, change state.
- Table notation: each entry is 3 characters **write–move–next state**, e.g. `1RB`. The compact form puts rows in order A0 A1 _ B0 B1 _ …, e.g. `1RB1LB_1LA1RZ`. `---` means an unused or undefined transition.
- Start on an all-zero tape in state A. The halting transition counts as a step. Halting transitions are written `1RZ`/`1RH`.
- Encoding functions on the tape: input nᵢ is written as nᵢ+1 consecutive 1s, separated by 0s. The output is the number of 1s on the tape at the end.
- **Thm 25.8:** Turing-computable = recursive.
- **Def 25.8:** a system is Turing complete (Turing完备) if it can compute every Turing-computable function.
- **Conjecture 25.1 (Church–Turing):** intuitively computable = Turing computable. The book stresses that this is a belief, not a provable theorem, because "human computation" cannot be made rigorous.
- Book's worked example (L490–518), which is the 2-state champion:

  |   | A | B |
  |---|---|---|
  | 0 | 1RB | 1LA |
  | 1 | 1LB | 1RH |

  The run is 000000A → 000100B → 000110A → 000110B → 001110A → 011110B → 011110(halt). It halts after 6 steps and leaves 4 ones.

### 1.4 Halting problem [BOOK] (L546–559)
- **Thm 25.9 (停机定理):** no Turing machine can decide, for every Turing machine, whether it halts.
- Proof sketch as the book gives it: suppose decider A outputs true/false on (the code of) any machine. Build B, which runs A and then loops forever if A says true and halts if A says false. Feed B's code to A. If B halts, A says true, so B loops. If B loops, A says false, so B halts. Contradiction.
- For teaching, make the self-reference explicit: B(x) asks A about "machine x run on input x", and then we run B on its own code. This is standard and the book leaves it implicit [SUPP].

### 1.5 Turing degrees, arithmetical hierarchy [BOOK] (L560–630)
- **Def 25.9–25.11:** A ≤_T B means A is decidable by a machine with an oracle (神谕) for B. ≡_T is mutual reducibility, and a Turing degree is an equivalence class. **0** (written ∅ in the book) is the degree of the computable sets.
- **Def 25.12 (Turing jump):** X′={x | φ_x^X(x) is defined}, i.e. "the halting problem relative to X". This gives ∅ <_T ∅′ <_T ∅″ < …, with transfinite jumps ∅^(α) for recursive α.
- ∅′ is the halting problem. ∅″ is the totality problem ("does the machine halt on all inputs"). Truth of Peano arithmetic sentences has degree ∅^(ω).
- There are intermediate degrees ∅ < a < ∅′, 2^ℵ₀ degrees in total, and incomparable degrees. Least upper bounds always exist; greatest lower bounds need not.
- **Def 25.13:** Σn, Πn, Δn. **Thm 25.11 (Post):** R∈Δ_{n+1} ⇔ R is recursive in ∅^(n); Σ_{n+1} ⇔ r.e. in ∅^(n); Π_{n+1} ⇔ co-r.e. in ∅^(n).

### 1.6 Kleene's O [BOOK] (L631–821)
- **Def 25.15:** 0∈K with |0|=0. If |n|=α then |2ⁿ|=α+1. If φ_i(n) is <_O-increasing, then |3·5^i| = sup of the |φ_i(k)|. <_O is transitive. Examples: |2^0|=1, |2^2^0|=2, and |3·5^i|=ω when φ_i(n)=2↑↑n.
- Fundamental sequences for α<ω₁^CK, and for ω₁^CK itself, **depend on the enumeration of Turing machines**.
- The book corrects several misconceptions about f_{ω₁^CK}:
  - It is not necessarily computable.
  - It is not "≈ BB".
  - Under a suitable enumeration it can be bounded by f_{ω+3} in the Wainer hierarchy, because diagonalising can even *reduce* the growth rate.
  - It has never been shown to be bounded by second-order BB.
  - It is always at least f_ω.

## 2. Uncomputable numbers (Ch.26)

### 2.1 Googology golf (大数高尔夫) [BOOK]
- **Thm 26.1:** C(n), the largest number output by a program of n characters in a fixed Turing-complete language, is non-recursive, with C(n) ~ ω₁^CK. The book's justification is that it diagonalises over all programs.
- Book convention: the growth rate of a non-recursive function is written with ω₁^CK = sup{0,1,ω,ε₀,SVO,LVO,…}. The book notes that strictly it should be Ω (the least non-recursive ordinal), not the admissible ω₁^CK, but says the two are the same here.
- Footnote: non-recursive does not mean big. Chaitin's Ω is uncomputable but less than 1, and the inverse of BB is uncomputable but grows slowly.
- JavaScript golf ladder (Discord JS golf). Some anchors:
  - `9e999`
  - `9**9**9e9`
  - `for(a=i=9;i--;)a**=a` (tetration level)
  - `f=x=>x&&9**f(x-1);f(f(9))`
  - Further programs reach f_ω, ω+k, ω², … up to φ(n−1,0) via the family m_n(x)
  - `for(M=1,g=x=>y--?g(g(x),y=x):-~x%M;!g(y=63);)M*=2` (49–50 characters) computes the Laver table, about q(7). Its growth rate is believed to be PTO(ZFC+I3).
- Brainfuck: BF(n) is the largest output of a halting n-symbol program.
  - BF(15) ≥ 16 with `++++[>++++<-]>.`
  - BF(30) ≥ 256
  - BF(45) ≥ 2↑↑9−2
  - BF(89) > f_{ω+1}(2↑↑↑6−2) > G(64). The book prints the same code for 45 and 89, which looks like a copy error.
- Kolmogorov complexity K(n) is uncomputable but grows slowly. It is roughly an inverse of C(n).

### 2.2 Busy Beaver: definitions and conventions [BOOK] — **important notational warning**
- **Def 26.1 (L1608):** "一个能够停机的n状态Turing机所能够扫过的最大格子数称为Busy Beaver函数，记为Σ(n)或BB(n)." Literally this says "max number of cells swept". But every value the book gives (4, 6, 13, 4098) is the **maximum number of 1s left on the tape** (Rado's Σ, the ones function). Read Σ(n) as "max ones".
- **Def 26.2 (L2541–2542):** "最大移动函数S(n)（有时我们也把这个函数称为BB(n)）": the maximum number of **steps** before a halting n-state machine stops. So the book uses the name "BB(n)" for **both** Σ and S. The section title "BB(5)的证明" refers to S(5).
- Model: n states, 2 symbols, blank tape, halt transition counted as a step, halt state not counted in n.
- Total number of n-state machines is (4n+4)^{2n} (L4758).
- **Course recommendation:** follow modern usage (bbchallenge, Wikipedia), where **BB(n)=S(n)** (steps) and Σ(n) is ones. Say explicitly that the book sometimes writes BB for Σ.
- Growth rate: Σ(n) ~ ω₁^CK (26.12).

**Collatz-like rule of the BB(5) champion [BOOK] (L1974–2108):** let g(n) = 0^∞ <A 1ⁿ 0^∞. Then:

### 2.3 Why BB beats every computable function
- **[BOOK]** The book only asserts Σ(n) ~ ω₁^CK. For C(n) it says it "exceeds every computer program (equivalent to enumerating all recursive functions and diagonalising)". For the oracle construction (§26.8) it says that with a halting oracle you can compute Σ(n) by enumerating the n-state machines, keeping the halting ones, running them, and taking the maximum. It also says Σ is uncomputable because the halting problem is.
- **[SUPP] Standard proof idea for the course (Rado):**
  1. If BB were computable, the halting problem would be decidable: run M for S(n) steps, and if it hasn't halted it never will. Contradiction.
  2. Domination: let f be any computable function, and set g(n)=f(2n)+f(2n+1) or similar to make it monotone. A machine with c states can compute g. Prepend a machine with ~n states that writes n ones, then run g twice. That uses n+O(1) states and writes at least g(g(n)) ≥ g(n)+1 ones. So Σ(n+c) ≥ g(n)+1 > f(n), and with a little more bookkeeping Σ(n) > f(n) for all large n.
- **[BOOK] Proof-theoretic version (L4742–4746):** no arithmetically sound, computably axiomatised theory T proves all values of S. For each such T there is an n_T such that for every n ≥ n_T, T proves no statement "S(n)=k". The reason: a machine with n_T states can search for a proof of a contradiction in T. Knowing S(n_T) would let T prove its own consistency, contradicting Gödel's second incompleteness theorem. n_T measures the strength of T.

### 2.4 ZFC independence and open conjecture machines — exact numbers in the book [BOOK] (L4597–4756)
- Goldbach conjecture: a **25-state** machine halts iff Goldbach is false. You would only have to run it S(25) steps.
- Erdős conjecture (for n>8, 2ⁿ written in base 3 contains a digit 2): **15-state** machine, or a 4-colour 5-state machine, so S(15) or S(5,4) would settle it.
- Riemann hypothesis: **744-state** machine, so S(744) would settle it.
- Laver table function finite ⇔ a **64-state** machine halts. Note that §26.2 also says 67 states for the lower bound.
- Weak Collatz conjecture: **124-state** machine, or a 4-colour 43-state one, so S(124) or S(43,4).
- **ZFC independence: "最新的结果指出，存在一个432状态的Turing机，它的停机性不能够在ZFC之中得到判定". So S(432) is undecidable in ZFC.** The book's statement is "for every consistent meta-natural m, 1+…+1 (m times) = S(432) is unprovable in ZFC". The book does **not** mention 7918, 748 or 745. 432 is its only ZFC figure.
- The book's caveat (L4658–4660): this is circular in practice. Computing S(25) would require deciding the Goldbach machine anyway.
- Friedman: γ(Z,12) is independent of ZFC; Θ(4,7) < 2^2^452408 and its exact value is independent of ZFC+I1; LEQ(8) has an equivalence-class count ZFC cannot compute.

### 2.5 BB(5) proof (§26.3) [BOOK]
- Epigraph: a 1990 prediction that Σ(5)=4098 and S(5)=47,176,870 would never be proved. Attributed "——BBChallenge合作组, 2025".
- The proof is Coq-BB5 (bbchallenge), done in Tree Normal Form (TNF, 树标准形式). TNF-1RB fixes A0→1RB, which is enough for Σ. Checking S needs more machines.
- Pipeline, as (non-halting / halting / total):

  | Decider | Non-halting | Halting | Total |
  |---|---|---|---|
  | Loops (循环) | 126,994,099 | 48,379,711 | 175,373,810 |
  | NGramCPS (n图闭合位置集) | 6,005,142 | 0 | |
  | RepWL (重复词名单) | 6,577 | 0 | |
  | FAR (有限自动机约化) | 23 | 0 | |
  | WFAR (加权有限自动机约化) | 17 | 0 | |
  | Long halters (run to 47,176,870 steps) | 0 | 183 | |
  | Sporadic machines, proved individually (零散机器) | 13 | 0 | |
  | 1RB-reduction | 24 | 0 | |
  | **Total** | **133,005,895** | **48,379,894** | **181,385,789** |

- Unifying idea, the Closed Tape Language (封闭磁带语言, CTL). Find a set C of configurations that (1) contains the all-zero start, (2) is closed under a step, and (3) contains no halting configuration. Then the machine never halts. Regular CTL means C is a regular language (finite automaton). This is a great high-school-friendly proof technique, essentially an invariant.
- The same method gives S(4)=107 (858,909 machines) and S(2,4)=3,932,974 (2,154,217 machines). S(4) and S(2,4) need only regular deciders. S(5) seems to need irregular ones, so there is a gap between 4 and 5.
- Hardest machines:
  - Skelet #1: a translated cycler with pre-period ≈5.42×10⁵¹ and period 8,468,569,863.
  - Skelet #10: a double Fibonacci counter (Zeckendorf).
  - Skelet #17: the last 5-state machine solved, related to Gray code.
  - Also "Finned #3" and "Skelet #34".
- Classification of 2-state TNF-1RB machines (106 total): 14 cyclers, 88 translated cyclers, 3 bouncers, 1 counter, and the rest halt. 3-state machines: 15,064 in TNF-1RB. 4-state: 2,744,516.

### 2.6 Collatz-like "cryptids" and open 6-state problems [BOOK] (L4770–5066)
The book uses "类Collatz行为", not the word "cryptid".
- **AntiHydra (6 states):** `1RB1RA_0LC1LE_1LD1LC_1LA0LB_1LF1RE_---0RA`. With A(a,b)=0^∞1^a 0 1^b E> 0^∞:
  - A(a,2b) → A(a+2, 3b+2)
  - A(0,2b+1) → halt
  - A(a+1,2b+1) → A(a, 3b+3)

  Orbit: A(0,4)→A(2,8)→A(4,14)→A(6,23)→A(5,36)→A(7,56)→A(9,86)→…. The book's heuristic halting probability is ((√5−1)/2)^1073720885 ≈ 4.841×10^−224394395. "Very likely non-halting, but unproved."
- **Luci's Moonlight (6 states):** `1RB0RD_0RC1RE_1RD0LA_1LE1LC_1RF0LD_1RZ0RA`. It produces c₀=0, c₁=14, c₂=11292, c₃≈10^2901.92, …. If it survives 13 cycles it beats the Σ(6) champion. The book estimates a ~5% chance of that.
- **Hydra (2 states, 5 colours):** C(a,b) rules C(2a,0)→halt-ish; C(2a,b+1)→C(3a+3,b); C(2a+1,b)→C(3a+3,b+2). After more than 4×10⁶ iterations b=2005373, giving a halting probability ≈ 4.168×10^−419099.
- **Bigfoot (3 states, 3 colours):** after 2.4×10⁷ iterations a=3999888, giving a halting probability ≈ 2^−3999889 ≈ 2.697×10^−1204087. The book prints the same code for Bigfoot as for Hydra, which is a copy error. Fetch the correct code from bbchallenge before using it.
- The book also asks (L4768): if the Church–Turing thesis holds and humans are equivalent to Turing machines, will some BB values never be known?

### 2.7 BBλ, TR, Friedman, Betti [BOOK, skim]
- **BBλ(n):** the largest normal-form output (Church numeral) of an n-bit closed binary lambda calculus term. BLC encoding: blc(n)=1ⁿ0, blc(λT)=00 blc(T), blc(TU)=01 blc(T) blc(U). Example: λfx.f(fx) = `0000011100111010`.
  - Values: BBλ(1..3)=0, 4, 0, then 6–20 equal n, then BBλ(21..33)=22, 24, 26, 30, 42, 52, 44, 58, 223, 160, 267, 298, 1812.
  - BBλ(34)=5·2^(2^2^2)+6=327686; BBλ(35)=5·3^3^3+6=38,127,987,424,941; BBλ(36)=5·2^(2^2^3)+6=5·2²⁵⁶+6≈5.79×10⁷⁷; BBλ(37)=BBλ(35)+2. The book's typesetting garbles the "5·" and the exponent towers; I checked these forms against the printed values.
  - Larger bounds: BBλ(49) > Graham; BBλ(111) > f_{ε₀+1}(4); BBλ(404) > f_{PTO(Z₂)+1}(4); BBλ(1850) > Loader's number.
- **TR(T,n)** (Def 26.3): the least N such that every machine whose halting is provable in T within n symbols halts within N steps. It is computable for recursive T, beats every function provably total in T, and needs Σ₁-soundness to be total. Friedman's "transcendental integer" is TR(ZFC, 2^1000). Fish's I0(n)=TR(ZFC+I0, n).
- Betti numbers of finitely presented groups: b_k(n) ~ Σ₃ (third-order BB), and c(n) ~ Σ₅.

### 2.8 Oracle machines and higher-order BB [BOOK] (§26.8, L6618–6659)
- A second-order Turing machine, or oracle machine (神谕机/预言机), can do everything a Turing machine does and also decide whether any first-order machine halts.
- Computing Σ(n) with such a machine: number all machines (1–64 are the 1-state ones, 65–20801 the 2-state ones, 20802–16798018 the 3-state ones), ask the oracle which halt, run those, and take the maximum.
- Σ₂(n) is the maximum for halting n-state second-order machines, with Σ₂(n) ~ ω₂^CK. In general Σ_m(n) ~ ω_m^CK and Σ_ω(n) ~ ω_ω^CK.
- In §26.11 the oracle hierarchy is written ∅, ∅′, ∅″, ….
- The book's position is that "ω_α^CK" here is a conventional growth-rate label. Strictly these are the non-recursive ordinals relative to the oracles.

### 2.9 Ξ function [BOOK] (§26.9)
- Goucher's Xi function uses SKI combinators with Ix⇒x, Kxy⇒x, Sxyz⇒xz(yz), plus an oracle combinator Ω: Ωxyz⇒y if x reduces to I, else z. Ξ(n) is the largest finite output size from n symbols. Paradoxical self-referential terms are ignored.
- Example reduction: SKS(KIS) ⇒ K(KIS)(S(KIS)) ⇒ KIS ⇒ I.
- Values: Ξ(1..7)=1, 2, 3, 4, 6, 17, 51. Lower bounds Ξ(8)≥137, Ξ(9)≥519, Ξ(10)≥1041, Ξ(11)≥2085, Ξ(12)≥4173; Ξ(n) > 261×2^(n−8)−3 for n≥9.
- Champion terms: Ξ(5): SSS(SI); Ξ(6): SSS(SI)S; Ξ(7): SSS(SI)SΩ.
- Large bounds: Ξ(30) > f_{ω+2}(2) > G(64); Ξ(2120) > f_{ε₀}(5).
- Growth rate: Ξ(n) ~ φ(1,0)^CK, where the book defines φ(α)^CK = ω_α^CK.

### 2.10 ITTM and hypercomputation [BOOK, skim]
- Zeno machine: a step takes 1/2ⁿ seconds, so ω steps fit in 1 second and it can solve the halting problem.
- ITTM (Hamkins–Lewis), Def 26.22: 3 tapes; at limit stages each cell takes the limsup and the machine enters a special limit state. Σ∞(n) is the BB for ITTMs.
- Writable, clockable, eventually writable and accidentally writable ordinals give λ, γ, ζ, Σ.
- **Thm 26.23:** ω₁^CK ≪ λ = γ < ζ < Σ.
- **Thm 26.24:** ζ is the least Σ₂-extendible ordinal, i.e. L_ζ ≺_{Σ₂} L_Σ.
- O⁺ and O⁺⁺ are Kleene's O generalised to ITTMs.
- §26.11 lists 13 hypercomputation models and maps them to Δ₁, Σ₁, Δ₂, …, Δ_ω levels.
- Conjecture 26.1 gives three physical Church–Turing variants (mathematical, physical, all processes). The book's conclusion: "no hope seen so far of building a hyper-Turing machine".

## 3. Undefinable numbers (Ch.27)

### 3.1 Rayo's number — exact content [BOOK] (L7088–7766)
- **History:** the 2007 MIT "Big Number Duel" between Agustín Rayo and Adam Elga. Rule: no primitive semantic vocabulary, e.g. "the least number bigger than any number named so far" is banned. Rayo won.
- **Informal definition (L7095):** Rayo(n) is the smallest natural number that cannot be defined by a first-order (set-theory) sentence of n symbols. **Rayo's number = Rayo(10^100)** (27.1).
- **Formal definition (Def 27.1, L7158–7177), transcribed:**

  ```
  Let [φ],[ψ] be Gödel-coded formulas, s,t variable assignments.
  Sat([φ],s) :=
  ∀R { { ∀[ψ],t : R([ψ],t) ↔
          ([ψ]="xi ∈ xj" ∧ t(xi) ∈ t(xj))
        ∨ ([ψ]="xi = xj" ∧ t(xi) = t(xj))
        ∨ ([ψ]="(¬θ)"    ∧ ¬R([θ],t))
        ∨ ([ψ]="(θ∧ξ)"   ∧ R([θ],t) ∧ R([ξ],t))
        ∨ ([ψ]="∃xi(θ)"  ∧ ∃t′ : R([θ],t′))   (t′ = t with xi changed)
      } ⇒ R([φ],s) }
  ```

  m is **Rayo-nameable (Rayo可命名的)** if some formula φ(x₁) with fewer than n symbols, whose only free variable is x₁, satisfies:
  1. there is an assignment s with x₁:=m such that Sat([φ(x₁)],s);
  2. for every assignment t, Sat([φ(x₁)],t) implies t(x₁)=m.

  **Rayo(n) is the least number greater than every number Rayo-nameable with n symbols.**
- Primitive symbols: ∈, =, ¬, ∧, ∃. Variables range over the whole universe V. Naturals are von Neumann ordinals: 0=∅, 1={∅}, 2={∅,{∅}}.
- **Length convention used for the small values (27.15–27.16):** L(xi∈xj)=3, L(xi=xj)=3, L((¬A))=L(A)+3, L((A∧B))=L(A)+L(B)+3, L(∃xi(A))=L(A)+4. A variable counts as 1 symbol. So below 10 only lengths 3, 6, 7, 9 occur.
- **Exact small values the book claims are proved (by near-exhaustive search, L7193–7197, 7250–7275, 7472):**
  - Rayo(0)=…=Rayo(9)=0. Every formula of length ≤9 is a tautology, a contradiction, or not a definition. There are 82 distinct length-9 formulas.
  - Rayo(10)=…=Rayo(19)=1. The only number-naming formula of length 10 is ¬∃x_i(x_i∈x₁), "x₁ is empty", which names 0.
  - **Inconsistency to flag:** the formal definition says "fewer than n symbols". But Rayo(10)=1 requires the length-10 formula for 0 to count at n=10, i.e. "at most n". The course should pick one convention (Rayo's original wording is "less than a googol symbols") and state it.
- **Lower bounds:**
  - Rayo(30) ≥ 2: 1 is named by (∃x₂(x₂∈x₁) ∧ (¬∃x₂((x₂∈x₁ ∧ ∃x₃(x₃∈x₂))))), which has length 30 (I checked the count).
  - Rayo(56) ≥ 3 (formula for 2)
  - Rayo(88) ≥ 4 (formula for 3)
  - General: **Rayo(34+20n) > n** (27.104)
  - Using the macros FormChain, IsV5, IsOrdinal and Wedges…With, Is65536(x) uses 340 symbols, so **Rayo(260+20n) > 2↑↑n**. Hence Rayo(320) > 16, Rayo(340) > 65536, Rayo(360) > 2^65536, Rayo(380) > 2^2^65536.
  - Encoding a Turing machine in set theory (ordered pairs, ℕ, +, Div2, Mod2, IsTranFunc, DefConf, DefSteps, DefShift) gives **Rayo(7901) > S(2^65536)**, optimised to **Rayo(7339) > S(2^65536−1)**. "The growth rate of Rayo far exceeds BB."
  - Gonz0TheGreatt's ML(n) (truth in a particular set rather than V): Rayo(11424+42n) > ML(2↑↑n), and ML(2n+13) ≥ 2↑↑2n.
- **Berry paradox motivation (L7150–7157):** "the smallest natural number that cannot be determined with twenty characters" (不能用二十个字确定的最小自然数) is itself a phrase under 20 characters, which is a paradox. The book blames the vagueness of natural language. Rayo's rules are precise, so the paradox doesn't arise. The set-theoretic reason is that "Sat" for the *object* language is defined in the *meta* language, by Tarski undefinability [SUPP explanation]. Rayo(n) is also different from "the least number not output by n characters of code". Programs are recursive, first-order logic over V is not, and its descriptive power is far greater.
- **Growth rate (L7758–7763):** "如果将数列按照其增长速度排序，那么Rayo函数的增长率似乎也应当对应一个序数σ, Rayo(n)∼σ, 这里的σ应当是一个**非递归的可数序数**. …目前尚没有关于σ的可靠估计."
- **Controversy (L7764–7766), quoted:** "关于Rayo数的定义尚存在一些争议。考虑到使用一阶逻辑公理时必须预先恰当地指定所使用的模型，要为Rayo数给出更可靠的定义还需要进行许多相当艰深的严格化工作。根据目前的分析来看，Rayo数可能仍然不是良定义的；即使它是良定义的，其强度可能也难以达到预期。" In English: you must specify the model (V) in advance, and quantifying over all relations R in the Sat definition is second-order over V. Rayo's number may not be well-defined, and even if it is, its strength may fall short of expectations.
- **Why it can be well-defined meta-theoretically [SUPP, consistent with §27.2]:** Sat for first-order set theory over V is definable in second-order set theory (e.g. Morse–Kelley/MK), or in ZFC with a truth predicate. In such a metatheory, "m is the unique object satisfying φ(x₁) in V" is meaningful, and Rayo(10^100) is a specific number. Within ZFC itself, full truth for V is not definable (Tarski), so you can't write down Rayo(n) as a ZFC term. That is exactly why the number is "undefinable" in the object theory.

### 3.2 How to define undefinable numbers (§27.2) [BOOK], after p進大好きbot
Checklist:
1. Fix the underlying logic F (default: first-order predicate logic).
2. Fix the language L (default FOST, first-order set theory).
3. Fix the axioms T (default ZFC). Precise schema choice depends on L, higher-order set theory must be axiomatised precisely, and definability in a formalised theory FT must itself be defined in the base theory.
4. Use only notions defined in T. Don't use truth or definability intuitively. "Skipping the actual definition solves nothing."

### 3.3 Large Number Garden Number (大数花园数, LNG) [BOOK] (§27.3)
- The book lists attempts to beat Rayo: Fish Number 7, BIG FOOT, Little Bigeddon, Sasquatch, Oblivion, Utter Oblivion. "All were eventually shown to be ill-defined, or not genuine extensions of earlier numbers." **The only survivor is p進大好きbot's Large Number Garden Number.** But "we still know very little about it, and it is still unclear whether it is well-defined."
- Construction:
  1. Take the language L = {∈} plus a unary function symbol U.
  2. Formalise L and ZFC inside ZF_L.
  3. Add a Henkin function symbol ⌜Θ⌝.
  4. T = ZF_L ∪ {U1, U2, U3}:
     - U1: for every ordinal α, U(α) ⊨ ZFC⌜L⌝ with Henkin axioms
     - U2: coherence, ⌜U⌝^{U(α)}(β) = U(β) for β<α
     - U3: |U(α)| = V_β with the true ∈
  5. CNF: ℕ→ε₀ codes ordinals via prime factorisation.
  6. Definable(x₀,x₁,x₂) means U(CNF(x₁)) ⊨ "x₂ defines x₀".
  7. f(n) is the sum of all m definable with i<n and code(P)<n. This f is uncomputable.
  8. **LNG = f^{10}(10↑^{10}10)** (27.196).
- Claim: T contains second-order ZFC and MK⁺, so f is expected to beat Rayo, and for large inputs to beat anything that diagonalises MK⁺.

### 3.4 DaVinci number [BOOK] (§27.4)
- Proposed by DaVinci103 in 2024. The idea: Rayo and LNG are defined in *recursive* theories. Use a meta-theory to build a non-recursive theory 𝒯 that has models M(t) of every recursive theory t (with standard ℕ), then define a number over it.
- Language hierarchy A_n with terms built from M(·), and truth relations R_n.
- N = the least number greater than every k such that some A_{10^100}-formula φ satisfies ∀x₀[x₀=k ⇔ ∀x₁∃x₂…∃x_{10^100} R_n(φ,x₀,…)].
- "We do not yet know whether the DaVinci number is well-defined." It is expected to be ≫ LNG.

### 3.5 ω₁ as "the end of googology" — what the book actually says
- I found no statement in Part 7 or Part 8 that "ω₁ is the true end of googology". I searched every `parts/*.txt` for 不可数, ω1, 尽头 and 终点.
- What the book does say:
  - **[BOOK] p1 (L3544–3552 of p1):** "最小的非递归序数仍然是可数的，而最小的不可数序数…" Countable vs uncountable ordinals are introduced there. Uncountable ordinals appear only in proof theory and large cardinals, not as growth rates.
  - **[BOOK] p7 L7758–7762:** Rayo's growth rate σ "should be a non-recursive **countable** ordinal", and there is no reliable estimate of it.
  - **[BOOK] p3 §12.6 (L5598–5650):** the strongest "ordinals" used for non-recursive growth are countable ordinals that look uncountable inside a model, e.g. ω₁^L, which is countable if 0♯ exists. "All the strong non-recursive properties (reflection, stability, admissibility, gaps) are countable ordinals definable in L, hence below ω₁^L."
  - **[BOOK] p8 §28.9 序数尺 (ordinal ruler, L5400–5436 of p8):** maps a notation's ordinals into rational points of (0,1) using fundamental sequences. The book notes you can't biject the reals with the recursive ordinals. It is useful as a visual ruler for the course. §28.14 高阶增长率 says higher-order growth rates stabilise at BO. Neither section is about ω₁.
  - **[BOOK] p8 L10235:** in infinite chess, the bound on mate-in-α positions is ω₁ (an unrelated appearance).
- **[SUPP] If the course wants an "ω₁ is the ceiling" slide, justify it like this rather than citing the book:**
  1. FGH growth rates are only meaningful for ordinals that have fundamental sequences of length ω, i.e. countable limits.
  2. Any countable set of functions ℕ→ℕ is eventually dominated by a single function (diagonalisation). So no countable ordinal labels a "fastest" function, and the supremum of all the countable labels is ω₁.
  3. Every particular well-defined function, including Rayo, LNG and BB_α, gets a countable label (when a label exists at all, given the dependence on fundamental sequences). So the googology ladder climbs through countable ordinals forever and never reaches ω₁. In that sense ω₁ is the unattainable "end".

  Label this as the course's own synthesis, consistent with the book's statement that σ is countable.

## 5. Open problems mentioned in the book

- **BB(6) / Σ(6):** only lower bounds are known (>2↑↑↑5, "≥10↑↑15"). The book's epigraph says S(6) "will never be proved". AntiHydra is open (likely non-halting, heuristic halting probability ~10^−224394395). Luci's Moonlight is open (likely halts, ~5% chance of a new record).
- **Collatz-type machines:** Hydra (2-state 5-colour) and Bigfoot (3-state 3-colour) are open, with heuristic probabilities given. The book: "the computation of BB is closely tied to Collatz-type problems."
- Conjecture machines (Goldbach at 25 states, Erdős at 15, Riemann at 744, weak Collatz at 124) are open exactly as long as the conjectures are.
- **S(432)** is undecidable in ZFC, so in that sense permanently unknowable within ZFC. The book's question: does Church–Turing imply some BB values are humanly unknowable?
- **Exact relation between S and Σ:** conjectured S(n) ~ Σ²(n).
- **Space(6), num(5), and the Σi/Si values beyond 7** are open.
- **Growth rate of f_{ω₁^CK}** under a non-pathological enumeration is unknown, including whether it is bounded by any α-order BB.
- **Rayo:** the growth ordinal σ has no reliable estimate. Well-definedness is disputed ("may still not be well-defined; even if it is, its strength may fall short").
- **LNG:** well-definedness is unclear. **DaVinci:** well-definedness is unknown.
- **Physical hypercomputation** (Conjecture 26.1) is unresolved. The **Church–Turing thesis** itself is a belief, not provable.
- Friedman: how small k, d, c can be made in PVEQ(k,d,c) (the target is PVEQ(4,4,8)), and how far LEQ(8) can be lowered.

## 6. Recommendations for a high-school learner

**Prerequisites from earlier parts:**
- Up-arrow notation, tetration and Graham's number (Part 1). These are needed to read the BB lower bounds.
- Fast-growing hierarchy f_α and fundamental sequences, ordinals up to ε₀ and the idea of a recursive ordinal (Part 1 Ch.3). These are needed for "growth rate ~ ω₁^CK" and the golf ladder.
- Countable vs uncountable and recursive vs non-recursive ordinals (Part 1 L3535–3552). Ideally also the idea of ω₁^CK from Part 3 (non-recursive ordinals).
- Basic sets: von Neumann naturals 0=∅, 1={∅}, …, and V_n (for Rayo).
- Propositional and first-order logic basics: ¬, ∧, ∃, free vs bound variables. These can be taught inline.
- For the "why BB can't be computed in ZFC" story, a gloss of Gödel's incompleteness theorems (Part 5 proof theory). One paragraph is enough.
- Optional: Laver tables, BMS, Loader's number, used only as reference points in the bounds.

**Suggested teaching order:**
1. "What is an algorithm?" Use Turing machines first. They are the most concrete and visual, and the book's own BB examples use them. Put recursive functions and λ-calculus in an "other equivalent models" sidebar, and use the Ackermann diagonal as the hook.
2. Halting problem via the paradox game. Stress the self-reference.
3. BB defined as a game: "the best n-state machine that still halts". Fix the notation clash early with a callout box: BB(n)=S(n)=steps (modern), Σ(n)=ones, and the book uses BB for both. Show the values table and let students try to beat BB(2) by hand.
4. Why BB is uncomputable (it would solve halting) and why it outgrows everything computable (the Rado argument, §2.3). Keep it as a 3-line proof with a diagram.
5. Show the BB(5) champion's Collatz-like orbit, then the Collatz conjecture, then the cryptids (AntiHydra). This makes "unknowable" feel real.
6. BB(5) proof as a story about large-scale collaboration plus formal proof. Present CTL as "find an invariant", with one worked example.
7. Independence: the 432-state ZFC machine, and Goldbach (25), Riemann (744). Use the book's numbers and add a date note: these are the book's figures, and literature numbers change.
8. Ladder beyond BB: oracles give Σ₂, Σ_m; then Ξ; then ITTM. Keep this qualitative.
9. Rayo:
   - Berry paradox first. Then explain why a precise language fixes it (object language vs metalanguage).
   - Build formulas for 0 and 1 by hand with the symbol counter.
   - Then the staircase of bounds.
   - Then "Rayo beats BB" via Rayo(7339) > S(2^65536−1).
   - Finally the honest controversy paragraph.
